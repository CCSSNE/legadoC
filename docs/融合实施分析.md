## 当前代码架构分析

### 音频书架构

```
音频书打开流程：
BookTocLoadingActivity (已改) 
  → ReadBookActivity（现在）
  → 但 ReadBookActivity 调用 ReadBook 模型加载内容
  → ReadBook 不知道如何处理音频书！

音频书播放：
AudioPlay（单例）
  ├─ 管理当前播放状态
  ├─ 加载音频URL（WebBook.getContent）
  ├─ 章节切换逻辑
  └─ 调用 AudioPlayService 播放

AudioPlayService
  ├─ ExoPlayer 播放音频
  └─ 通知栏控制
```

### 普通书架构

```
普通书朗读流程：
ReadBookActivity
  → 用户点击朗读按钮
  → ReadAloud.play()
  → TTSReadAloudService（继承 BaseReadAloudService）
    ├─ 从 ReadBook 获取当前页内容
    ├─ 分段朗读（contentList）
    └─ 系统 TTS 或 HTTP TTS 朗读

BaseReadAloudService
  ├─ 管理朗读状态
  ├─ 创建朗读悬浮窗
  └─ 通知栏控制
```

## 第一阶段的真正目标

根据融合计划，第一阶段要实现：

### 1. 文字适配（核心）
**问题**：音频书可能没有完整文字内容，只有音频URL
**解决方案**：
- 检查 `BookChapter.resourceUrl` 是否存在
- 如果音频书有字幕，通过 `chapter.getVariable("lyric")` 获取
- 将字幕适配为 ReadBook 可显示的文本内容
- 如果没有字幕，显示简单的"正在播放音频"占位文本

### 2. 音频解构（核心）
**问题**：AudioPlay 是独立系统，与 TTS 朗读没有统一接口
**解决方案**：
- 创建 `ReadAloudEngine` 接口
- 实现 `SourceAudioEngine`（书源音频）
- 实现 `SystemTtsEngine`（系统TTS）
- 实现 `HttpTtsEngine`（HTTP TTS）
- BaseReadAloudService 支持切换引擎

### 3. 文字与音频映射
**问题**：音频播放位置与文字位置需要同步
**解决方案**：
- 音频时间 ↔ 字幕句子的映射
- 双击文字跳转到对应音频位置
- 音频播放时高亮对应文字

### 4. 进度条功能
**问题**：进度条只是空壳
**解决方案**：
- 根据当前引擎类型显示：
  - SourceAudioEngine: 00:00 / 15:30（时间）
  - TTS Engine: 段 3 / 15（段落）
- 拖动跳转功能
- 实时更新进度

## 技术挑战

1. **AudioPlay 与 ReadBook 的数据同步**
   - 当前章节索引
   - 播放位置
   - 章节切换

2. **两套服务的统一**
   - AudioPlayService（音频）
   - TTSReadAloudService（TTS）
   - 需要统一接口

3. **音频书可能没有文字**
   - 需要降级方案
   - 显示占位内容
