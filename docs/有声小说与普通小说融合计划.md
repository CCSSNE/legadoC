## 统一称呼

| 称呼 | 含义 | 当前实现 |
| --- | --- | --- |
| 听书页面 | 全屏的听书主界面 | 音频书 `AudioPlayActivity` |
| 朗读悬浮窗 | 阅读页上的紧凑听书控制条 | 普通书 `BaseReadAloudService` 动态创建的浮层 |

后续讨论中不再使用“音频播放页”“音频书页面”“小悬浮窗”等不稳定称呼。

## 已确认入口

### 听书页面

- 适用对象：当前为 `book.isAudio` 的音频书。
- 正常启动链路：`BookTocLoadingActivity` 根据 `book.isAudio` 启动 `AudioPlayActivity`。
- 播放服务：`AudioPlayService`。
- 代码入口：`app/src/main/java/io/legado/app/ui/book/toc/BookTocLoadingActivity.kt`、`app/src/main/java/io/legado/app/ui/book/audio/AudioPlayActivity.kt`。

### 朗读悬浮窗

- 适用对象：当前为普通书的 TTS 朗读。
- 播放服务：`TTSReadAloudService`。
- 创建入口：`BaseReadAloudService.createReadAloudFloatingView()`。
- 当前页面内模式：由 `BaseReadAloudService.showAppReadAloudFloatingWindow()` 挂到 `ReadBookActivity` 的 `decorView`；它包含继续阅读、暂停/继续和停止三个操作。
- 代码入口：`app/src/main/java/io/legado/app/service/BaseReadAloudService.kt`。

## 边界

- 当前两者是独立实现，分别由 `AudioPlayService` 与 `TTSReadAloudService` 驱动。
- 本文不把“听书页面”误指为普通书朗读，也不把“朗读悬浮窗”误指为系统通知。
- 后续融合应从这两个已确认入口收敛，避免在 Feature 内新增第三套听书界面或浮层实现。

## 迁移讨论稿

本节记录当前讨论达成的迁移顺序，供继续修改和补充。它不是实施完成状态，也不替代后续每个阶段的详细设计。

### 第零阶段：按四类信息收集事实

先不改造，先把关键数据与调用链收集清楚，并持续回填本文档。

1. 音频书的构成：书籍、章节、文字或字幕、音频地址、文字与音频对应关系、进度、缓存和书源规则。
2. 普通书的构成：正文解析、章节、段落、分页、阅读位置、双击听书、TTS 引擎和进度保存。
3. 音频书的界面：听书页面入口、控件、状态、`AudioPlay`、`AudioPlayService` 和真实时间进度。
4. 普通书的界面：普通阅读页面、听书菜单、朗读悬浮窗、`ReadAloudDialog`、TTS 服务和指哪读哪调用链。

### 第一阶段：音频书映射到普通阅读页面

音频书默认进入普通阅读页面，不再按书籍类型进入原来的听书页面。原听书页面保留，但从默认阅读入口中退出。

1. 文字适配：把音频书提供的文字或字幕适配为普通阅读页面可排版、翻页和定位的正文。
2. 音频解构：把书源自带音频从“音频书专属逻辑”中解构出来，作为一种听书引擎来源；它与系统 TTS、HTTP TTS 平级。
3. 文字与音频映射：把书源已有的文字和音频对应关系接入普通阅读页面已有的双击听书、指哪读哪能力。
4. 进度条：在普通阅读页面的听书菜单中增加进度条。
   - 使用书源音频引擎时，显示真实音频时间，并与句子或字幕对齐。
   - 使用普通 TTS 引擎时，显示章节段落进度；拖动位置映射到章节内对应段落并继续朗读。

第一阶段结束后，音频书和普通书共用普通阅读页面；音频书可选择书源音频，也可选择普通 TTS。

### 第二阶段：合并成一套听书 UI

第一阶段完成后，音频书已经进入普通阅读页面，原来只给音频书使用的听书页面不再承担默认阅读入口的职责。第二阶段利用这个听书页面，并把它和普通阅读页面中原来没有充分利用的朗读悬浮窗绑定起来，合并成一套完整的听书 UI。

```text
普通阅读页面 -> 朗读悬浮窗 -> 听书页面
```

这条入口不再区分音频书和普通书：

- 音频书在普通阅读页面中点击朗读悬浮窗，进入听书页面，继续控制当前的书源音频或 TTS 会话。
- 普通书在普通阅读页面中点击朗读悬浮窗，也进入同一个听书页面，继续控制当前的 TTS 会话。

听书页面原本只服务有声小说，本阶段要让它同时兼容普通小说。第一阶段已经统一了听书引擎和进度条，因此听书页面不再根据书籍类型决定能力，而是根据当前引擎显示对应状态：

- 使用书源音频引擎时，显示真实音频时间进度，并保持音频、句子和正文位置对齐。
- 使用系统 TTS、HTTP TTS 等普通引擎时，显示章节段落进度；拖动进度条定位到章节内对应段落并继续朗读。

普通小说虽然没有成品音频和真实音频总时长，但已经具备段落进度、拖动定位和指哪读哪，因此可以完整使用原有听书页面。音频书相较普通书只多出一种书源音频引擎，以及该引擎提供的真实时间进度。

## 音频听书 UI

“音频听书 UI”指朗读悬浮窗、听书页面及两者之间的会话绑定。第二阶段一次完成这两部分的合并，并让整套 UI 同时服务音频书和普通书。
