### 阅读C 独有支持的书源能力

因为做了有声书和普通小说的界面融合，所以有声书源也可以用userhtml添加评论按钮之类的。
考虑到大量书源还是老标准，所以支持同一书名、同一作者的书，从普通小说带评论的版本把评论提取出来，添加到有声小说对应的段落里。

建议书源给每一段都加上评论泡，即使回复为零，因为本阅读C支持回复为零的评论泡自动收纳到长按文本悬浮窗中的评论按钮，可以实现任意段落，主动发评论。。

### 2026-08-17

**有声小说与普通小说融合**

- 统一阅读入口：有声书从书籍详情、目录和其他阅读入口进入时，默认进入普通阅读页，不再因为 `book.isAudio` 被强制分流到另一套阅读页面；原有书源音频能力保留为朗读引擎的一种来源。
- 保留身份，统一体验：音频书与文本书在数据层明确区分，避免同名书互相覆盖；书架和列表用音频标记告诉用户当前打开的究竟是哪一种书，同时不替书源校验或改写来源身份。
- 统一内容模型：书源提供的字幕或正文先适配为普通阅读页可排版的章节、段落和分页内容，阅读页继续负责排版、翻页、滚动和阅读位置；音频书不是被伪装成文本书，而是在同一个 `ReadBook` 阅读模型里增加了可映射的音频会话。
- 统一朗读引擎：系统 TTS、HTTP TTS 与书源音频平级接入 `ReadAloud` / `BaseReadAloudService`，由当前引擎决定进度语义——TTS 使用章节段落进度，书源音频使用真实时间进度；切换引擎时立即切换控制面板、进度条和语速控件，不再等待下一次播放回调。
- 接通文字与音频映射：增加字幕/正文映射和排版后段落定位，支持双击、点击段落和“指哪读哪”，可以从文本位置跳到对应音频，也可以从音频进度回到正文位置；映射失败会明确记录和提示，不用静默回退掩盖数据不一致。
- 听书页改为同一会话的另一种视图：全屏听书页同时兼容书源音频、系统 TTS 和 HTTP TTS。TTS 在听书页也能滚动段落、点击定位和继续朗读，返回阅读页时恢复当前章节、阅读位置以及播放/暂停状态。

**朗读悬浮窗与阅读页交互**

- 朗读菜单打开后，完整悬浮窗与菜单并存；点击菜单外部收起后，悬浮窗变为阅读页底部的“暂停播放 / 继续播放”控制块。
- 阅读页翻页后，底部控制块切换为“原进度 / 从本页听”，让用户明确选择回到朗读位置还是从当前页开始；重新打开朗读菜单时恢复完整悬浮窗和完整控制面板。
- 朗读菜单的播放控制行增加直接进入听书页的入口；进入听书页会隐藏阅读页悬浮控件，避免同一会话出现两套重复控制。
- 听书页更多菜单增加离线缓存和朗读引擎入口；离线缓存通知使用一个当前章节下载进度条，同时显示全书章节进度，例如 `10/66 章`。

**音频书源与朗读细节**

- 新有声书默认语速调整为 `1.6`，已有用户自定义语速不被覆盖；书源音频和 TTS 的语速控件随引擎切换即时更新。
- 修复书源音频字幕、正文和排版段落数量不一致导致的播放失败，统一映射到排版后的段落位置。
- 朗读设置页统一控制行高度和间距，移除多余的 `10dp` 留白，使进度、计时、语速和底部操作区对齐。
- 增加关闭书源底部消息、关闭全部底部消息的设置，朗读九宫格菜单中的相关入口改为进入朗读设置，而不是误入主设置。
- 恢复换源页和播放模式的上游布局，精简朗读引擎菜单动作；音频书封面、书架列表和列表布局的音频标记统一到封面右上角附近。

**目录与其他界面修复**

- 统一内容规则菜单的表面和操作入口，目录增加反向显示能力；菜单、弹窗和目录操作继续沿用同一套表面与底部操作区规则。
- 删除已经失效的融合计划规则，保留当前实际采用的统一引擎、统一阅读入口和统一会话设计。

**UI 结论**

- 这次融合不是把有声书简单塞进文本阅读页，而是把“书籍身份”“阅读内容”“朗读引擎”“进度单位”“悬浮控制”和“全屏听书”拆开后重新组合：来源身份仍然准确，用户入口和操作体验却只有一套。
- 最终 UI 已经形成统一的阅读信息层级、底部控制和透明表面风格，整体非常接近番茄阅读的成熟布局。直白一点说：番茄在阅读和听书 UI 上值得薅的那部分，基本已经被我们薅秃了，而且还补上了本地书、在线书和有声书共用一套会话的能力。
